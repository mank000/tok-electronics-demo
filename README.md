# ток. — учебный магазин электроники

Одна адаптивная Django-страница работает в обычном браузере и как Telegram Mini App. В проекте есть PostgreSQL, Django Admin, каталог из 29 демотоваров, корзина, заказы, личный кабинет, отзывы, вопросы, возвраты, подборки, демооплата и тестовый виджет ЮKassa. Реальных списаний нет: подключать можно только тестовый магазин; юридические страницы — заглушки.

## Запуск с нуля

Нужны Docker и Docker Compose. Команды выполняются в каталоге проекта:

```bash
cp .env.example .env
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Вставьте случайное значение в `DJANGO_SECRET_KEY` и **другое** случайное значение в `POSTGRES_PASSWORD`. Данные бота и отдельный секрет учебной оплаты можно задать позже в админке; до настройки секрета демооплата не работает. Затем:

```bash
docker compose up -d --build web
docker compose exec web python manage.py seed_catalog
docker compose exec web python manage.py seed_demo_feedback
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py test store
```

Откройте <http://localhost:8008/> и админку <http://localhost:8008/admin/>. Миграции применяются при старте `web`. `seed_catalog` добавляет подробные демонстрационные описания и характеристики, сохраняет уже отредактированные товары. `seed_demo_feedback` добавляет по два вопроса с ответами и два отзыва с оценками на каждый из 29 товаров, а также десять явно помеченных учебных заказов, необходимых для проверки отзывов после покупки. Все примеры в карточках отмечены как демо; команда работает только при `DJANGO_DEBUG=1`, повторный запуск не создаёт копий и не публикует скрытое модератором. Остановить: `docker compose down` (данные останутся в volumes). `docker compose down -v` удалит БД и изображения.

При `DJANGO_DEBUG=1` магазин и админка принимают формы из встроенного браузера с `Origin: null` только на хостах из `DJANGO_DEMO_NULL_ORIGIN_HOSTS`. Для HTTPS этот адрес также должен быть указан в `DJANGO_CSRF_TRUSTED_ORIGINS`. CSRF-токен и cookie по-прежнему обязательны; остальные хосты проходят обычную проверку origin Django.

Для учебной оплаты откройте в админке **Подключение Telegram и оплаты** и задайте секрет оплаты длиной от 32 символов. Его можно создать командой `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'`. В этом же разделе задаются токен бота, Client ID и Client Secret Telegram Login, ID и секретный ключ **тестового** магазина ЮKassa. Раздел доступен только суперпользователю. Секреты сохраняются в БД в зашифрованном виде; после сохранения поля остаются пустыми, а статус показывает, задано ли значение. Пустое поле при повторном сохранении оставляет текущий секрет, отдельная галочка удаляет его из админки и возвращает запасное значение из `.env`. Для шифрования используется `DJANGO_SECRET_KEY`: сохраните его и резервную копию БД, смена ключа сделает ранее сохранённые секреты нечитаемыми. Для ЮKassa также настройте публичный HTTPS webhook в кабинете тестового магазина: `https://<ваш-домен>/api/pay/yoo/webhook/`.

## Переменные окружения

Пример без секретов — [`.env.example`](.env.example). `.env` игнорируется Git.

| Переменная | Назначение |
| --- | --- |
| `DJANGO_SECRET_KEY` | Секрет Django, длинное случайное значение |
| `DJANGO_DEBUG` | `1` для локальной демонстрации; демооплата требует `1` |
| `DJANGO_ALLOWED_HOSTS` | Хосты без схемы, через запятую |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Полные origin с `https://` для туннеля |
| `DJANGO_DEMO_NULL_ORIGIN_HOSTS` | Хосты локальной демонстрации, для которых разрешён `Origin: null` при наличии CSRF-токена |
| `POSTGRES_*` | База, пользователь, пароль PostgreSQL |
| `BOT_TOKEN` | Необязательный запасной вариант для токена BotFather |
| `BOT_USERNAME` | Необязательный запасной username бота без `@` |
| `BOT_APP_SHORT_NAME` | Необязательное запасное short name Mini App |
| `PUBLIC_BASE_URL` | Необязательный запасной публичный HTTPS URL |
| `SHOP_CHAT_ID` | Необязательный запасной ID чата магазина |
| `PAYMENT_WEBHOOK_SECRET` | Необязательный запасной секрет HMAC учебной оплаты |
| `TELEGRAM_LOGIN_CLIENT_ID` / `TELEGRAM_LOGIN_CLIENT_SECRET` | Необязательные запасные реквизиты Telegram Login |
| `DEMO_PAYMENTS` | `1` включает учебную оплату только при `DJANGO_DEBUG=1` |
| `YOOKASSA_SHOP_ID` | Необязательный запасной ID **тестового** магазина ЮKassa |
| `YOOKASSA_SECRET_KEY` | Необязательный запасной секретный ключ **тестового** магазина ЮKassa |

Значения из админки имеют приоритет над соответствующими переменными `.env`; если значение в админке не задано, используется `.env`. Секреты, БД, пользовательские фотографии и `.env` не входят в Git. Обычный `compose.yaml` предназначен для локальной демонстрации.

## Подготовка публичного сервера

Отдельный `compose.prod.yaml` подготовлен для сервера с постоянным доменом: Caddy получает и обновляет HTTPS-сертификат, отдаёт собранную статику и загруженные фото, Django работает с `DEBUG=0`, а PostgreSQL и бот не публикуют порты. Этот стек использует отдельные тома (`tgapp-prod`), поэтому локальная демобаза не переносится автоматически. Нужны DNS-запись домена на сервер и открытые порты 80/443. До выбора сервера и домена запускать его некуда.

```bash
cp .env.prod.example .env.prod
python3 -c 'import secrets; print(secrets.token_urlsafe(64))'
# В .env.prod заполните SITE_DOMAIN, DJANGO_ALLOWED_HOSTS,
# DJANGO_CSRF_TRUSTED_ORIGINS, новый DJANGO_SECRET_KEY и POSTGRES_PASSWORD.
docker compose --env-file .env.prod -f compose.prod.yaml up -d --build
docker compose --env-file .env.prod -f compose.prod.yaml --profile bot up -d bot
./deploy/backup.sh
```

Не переносите короткий локальный `DJANGO_SECRET_KEY` на сервер. Секреты интеграций, сохранённые в админке, зашифрованы с его помощью: при переносе существующей БД с другим ключом их нужно заново внести в админке. Перед переносом данных проверьте резервную копию БД и папки `media` и отдельно восстановление на тестовом окружении. `deploy/backup.sh` создаёт закрытую копию БД и фото в `backups/`; настройте периодический запуск и хранение копий вне сервера. `/healthz/` проверяет доступность БД и используется Docker healthcheck. В `check --deploy` остаются только предупреждения о HSTS для всех поддоменов и preload: их нельзя включать без решения для всего домена.

Публичный стек готовит инфраструктуру, но **не разрешает начать реальные продажи сам по себе**: замените учебные товары, цены, политику обработки данных и оферту на согласованные реальные сведения; настройте резервное копирование и внешнее оповещение о сбоях. Сейчас ЮKassa интегрирована только с тестовым магазином и намеренно отвергает ответ настоящего магазина; при `DEBUG=0` демооплата выключена. Тестовая ЮKassa на публичном стеке по умолчанию тоже выключена, даже если её ключи сохранены в админке. Для отдельного учебного стенда можно явно установить `DJANGO_ALLOW_TEST_PAYMENTS=1`, но его заказы нельзя исполнять как оплаченные настоящими деньгами. До подключения рабочего эквайринга возможна только оплата при получении для самовывоза и городской доставки. Не подключайте боевой ключ ЮKassa к текущему коду.

Для тестирования ЮKassa не закрепляйте временный адрес `trycloudflare.com`: он меняется. По [официальной инструкции](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing) при регистрации можно перейти сразу к тестированию и создать тестовый магазин до подключения настоящего магазина. Если форма всё равно требует сайт и не принимает адрес туннеля, используйте будущий постоянный короткий домен или уточните ограничение у поддержки ЮKassa. URL уведомлений указывается отдельно после появления стабильного публичного HTTPS-адреса.

## Каталог и покупка в браузере

1. Найдите товар поиском или разделом, отсортируйте по цене. Скрытые товары не показываются.
2. На карточке товара со статусом «Под заказ» оставьте заявку «Хочу такой». Остальные товары добавьте в корзину.
3. Измените количество в корзине. Она сохраняется в `localStorage` этого браузера.
4. Оформите заказ: имя, телефон, получение, адрес для доставки, оплата, согласие. Для отправки в регионы оплата при получении запрещена. Сервер заново читает текущие цены и сохраняет их в позициях заказа.
5. При онлайн-оплате выберите шлюз: демооплату или ЮKassa. Демооплата позволяет имитировать успех и отказ. ЮKassa показывает встроенный виджет тестового магазина; после оплаты статус подтверждается сервером через API ЮKassa. Сохраните непредсказуемую ссылку на заказ.

Страницы обработки данных и оферты явно помечены как заглушки. Перед настоящими продажами их нужно заменить. Оплата при получении не вызывает демооплату.

## Telegram Mini App и бот

1. В `@BotFather` создайте бота (`/newbot`) и Mini App для этого бота (`/newapp`). Получите токен, username и короткое имя приложения. Настройте HTTPS URL приложения после запуска туннеля.
2. Запустите `docker compose --profile bot up -d bot`. В админке откройте **Подключение Telegram и оплаты** и задайте `BOT_TOKEN`, username бота и короткое имя Mini App. Бот ждёт настройки и подхватит её без перезапуска. Если бот уже получает обновления через webhook, отключите его перед long polling.
3. Отдельный чат магазина **не обязателен**: покупатели заходят через бота, Mini App или сайт, а владелец смотрит заказы и события в админке. Если владелец дополнительно хочет получать сообщения о заказах в Telegram, создайте свою группу/чат, добавьте бота и отправьте `/chatid`; бот ответит ID, который можно записать в админке. Без этого ID события магазина получают статус «Только в админке», а уведомления покупателям продолжают работать. Для сообщения покупателю он должен открыть личный чат с ботом и нажать `/start`.
4. Для локальной проверки HTTPS установите `cloudflared` и запустите `cloudflared tunnel --url http://localhost:8008`. Если QUIC не соединяется с edge, используйте `cloudflared tunnel --url http://localhost:8008 --protocol http2`. Скопируйте выданный `https://...trycloudflare.com` URL. В `.env` задайте `DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,<имя-хоста-туннеля>`, `DJANGO_CSRF_TRUSTED_ORIGINS=http://localhost:8008,https://<имя-хоста-туннеля>` и `DJANGO_DEMO_NULL_ORIGIN_HOSTS=localhost,127.0.0.1,<имя-хоста-туннеля>`, затем пересоздайте web: `docker compose up -d --force-recreate web`. Публичный адрес укажите в разделе подключений админки; в BotFather установите этот HTTPS URL для Mini App. Хосты и доверенные адреса Django остаются в `.env`, потому что нужны до обработки запросов.
5. Откройте `https://t.me/<bot_username>/<app_short_name>?startapp=product_phones-1`: должна открыться карточка товара. Из чата бота нажмите кнопку каталога и пройдите оформление. Проверьте заказ, оплату, уведомления в личном чате и запись о заказе в админке.

`Telegram.WebApp.initData` передаётся серверу без доверия к `initDataUnsafe`; сервер проверяет HMAC, `auth_date` и ID пользователя. Telegram не передаёт номер телефона автоматически. При первом открытии Mini App появляется короткая регистрация: имя уже предложено из Telegram, его можно исправить; кнопка вызывает системное окно `requestContact`. Только после согласия контакт с номером и Telegram ID приходит боту, и магазин сохраняет имя и номер. Можно продолжить без регистрации, но вход по коду в браузере до неё недоступен. Для получения контакта должен работать `bot` (`docker compose --profile bot up -d --build bot`). [Документация Mini Apps](https://core.telegram.org/bots/webapps).

### Поддержка через Telegram

Кнопка «Поддержка» на сайте и в Mini App открывает личный чат с тем же ботом через `https://t.me/<bot_username>?start=support`. Бот создаёт обращение; последующие текстовые сообщения попадают в его переписку. Сотрудник открывает **Поддержка** в Django Admin, читает сообщения и вводит ответ. Ответ сохраняется в истории и отправляется покупателю через существующую очередь Telegram. Отдельный чат магазина не нужен; если он настроен, туда приходит уведомление о новом сообщении без текста обращения. `/done` закрывает обращение, повторная `/support` начинает новое. Поддержка принимает сообщения только из личного чата с ботом; номер телефона для неё не запрашивается. Для отправки ответов должен работать процесс `bot` и пользователь должен открыть чат с ботом. [Deep linking Telegram](https://core.telegram.org/bots/features#deep-linking).

### Вход в тот же кабинет из Chrome

После регистрации в Mini App откройте `/account/` в Chrome, укажите переданный номер и нажмите «Получить код». Бот отправит шестизначный код в личный чат Telegram. Код действует 5 минут и принимается только в том браузере, где его запросили; есть ограничение попыток и частоты отправки. Номер, которого нет среди контактов, добровольно переданных этому боту, нельзя использовать для входа. Бот не умеет искать произвольный Telegram-аккаунт по номеру и начинать с ним переписку. Телефон не выводится в кабинете. Для реального сценария нужен настроенный `BOT_TOKEN`, работающий бот и доступный Telegram API. [Ограничения ботов](https://core.telegram.org/bots), [Bot API](https://core.telegram.org/bots/api).

Старый вход через Telegram Login остаётся дополнительным способом. Если он нужен, настройте **Login Widget / Web Login** для этого же бота в BotFather: добавьте публичный HTTPS-адрес и callback `https://<ваш-домен>/auth/telegram/callback/` в Allowed URLs, получите Client ID и Client Secret и сохраните их в админке в разделе **Подключение Telegram и оплаты**. `.env` остаётся запасным вариантом. [Инструкция Telegram Login](https://core.telegram.org/bots/telegram-login).

Гостевой заказ, оформленный в том же браузере перед входом, привязывается к Telegram ID при успешном входе. На другом устройстве войдите по тому же номеру. При оформлении заказа сохранённый номер подставляется в поле контакта, где его можно проверить и изменить.

Демооплата и виджет ЮKassa открываются внутри приложения. Если выбранный в виджете способ оплаты сам переводит на банковскую страницу, переход определяется ЮKassa. После возврата на заказ приложение проверяет статус через серверный API. Кнопка «Проверить статус оплаты» позволяет повторить проверку. Ссылка на заказ является ключом гостевого доступа, не передавайте её посторонним.

Для короткой записи экрана на телефоне: начните с `/start` и кнопки каталога → откройте товар по прямой ссылке → добавьте товар в избранное и корзину → оформите заказ → в демооплате нажмите «Отказ» → повторите и нажмите «Оплата прошла» → покажите кабинет, два чата с уведомлениями и в админке смените статус/укажите трек-номер → покажите уведомление покупателю. Уберите из записи реальные телефоны, токены и приватную ссылку заказа.

## Админка и уведомления

В админке доступны разделы, товары с несколькими изображениями, цены, наличие и скрытие, заказы, заявки, платежные события и уведомления. На странице товара видно количество заявок «Хочу такой». У заказа можно менять статус и трек-номер; изменения для покупателя ставят сообщение в очередь. Бот отправляет очередь независимо от транзакции заказа. Временные ошибки отправки повторяются автоматически до трёх попыток. События магазина без отдельного чата сохраняются со статусом «Только в админке». Остальные ошибки видны в «Уведомлениях»; неотправленные можно выделить и выбрать действие «Повторить отправку выбранных уведомлений».

Раздел **Аналитика магазина** в админке показывает данные за 6, 12 или 24 месяца: количество заказов и суммы по месяцам, средний оплаченный заказ, активные заказы и возвраты, популярные товары, заявки «Хочу такой», избранное и распределение по статусам, доставке и способам оплаты. Он доступен суперпользователю и сотрудникам с правом просмотра заказов. Демонстрационные заказы исключены. Количество заказов включает отменённые; сумма заказов и подтверждённые оплаты их исключают. Сумма заказов может включать ещё не оплаченные покупки. Платежи сейчас учебные, поэтому подтверждённые суммы нельзя считать фактической выручкой. Оплата при получении в них не входит. Поскольку отдельная дата оплаты пока не хранится, помесячные суммы распределяются по дате создания заказа.

В разделе «Настройки магазина» можно один раз создать запись и затем менять название, подпись, логотип, контактный телефон, почту, адрес самовывоза и реквизиты. Название и логотип показываются на витрине, контакты и заполненные реквизиты — в подвале сайта; приветствие бота использует актуальное название. Все поля, кроме названия и подписи, необязательны: без записи настроек магазин открывается с демоназванием. Реквизиты не превращают учебные страницы обработки данных и оферты в юридические документы.

В отдельном разделе «Подключение Telegram и оплаты» суперпользователь задаёт токен бота, username, short name Mini App, публичный HTTPS-адрес, ID чата магазина и секрет учебной оплаты. Изменения применяются к новым веб-запросам и следующему циклу опроса бота без перезапуска. При смене токена старые `initData` перестанут проходить проверку подписи; при смене секрета оплаты события, подписанные старым секретом, будут отклонены.

Загружаемые в админке JPEG, PNG и другие поддерживаемые растровые изображения приводятся к WebP с учётом ориентации камеры (основное фото товара до 1200×1200, превью до 480×480, логотип до 640×640). На странице товара в админке видны превью и порядок снимков. Источник демоизображений — **двенадцать оригинальных синтетических фотоснимков, созданных OpenAI imagegen для этого проекта**; сжатые исходники лежат в `store/seed_photos/`. Пять исходных снимков повторно используются в соответствующих разделах, у первых смартфона и ноутбука есть второй ракурс, а новые зарядка, чехлы и сумки получили отдельные изображения. Каждый товар получает локальный снимок; сторонних hotlink URL и лицензий на чужие фото нет. Это обобщённые изображения, не фотографии конкретных вымышленных моделей. Для настоящего магазина замените их собственными снимками.

## Проверки и платежный обработчик

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py test store -v 2
docker compose exec web python manage.py seed_catalog
docker compose exec web python manage.py seed_catalog
```

Последние две команды должны сохранить число товаров 29 и три подборки. Платежный endpoint `/api/payment/webhook/` принимает JSON `{"event_id":"...","attempt":"UUID","status":"paid|declined"}` и заголовок `X-Payment-Signature` = HMAC-SHA-256 от **сырых байтов** тела с `PAYMENT_WEBHOOK_SECRET`. События повторно не применяются. Браузер не вызывает этот endpoint: кнопки демооплаты вызывают серверный сценарий, который использует ту же функцию обработки событий. ЮKassa интегрирована отдельно: сервер создаёт платёж с ключом идемпотентности, выдаёт токен встроенному виджету и принимает уведомления на `/api/pay/yoo/webhook/`. Уведомление не меняет заказ напрямую: сервер запрашивает актуальный платёж у ЮKassa и сверяет ID, сумму, валюту, режим `test` и метаданные заказа. Укажите публичный HTTPS URL webhook в кабинете тестового магазина. Результат можно проверить кнопкой на странице заказа и без webhook. [Документация виджета](https://yookassa.ru/developers/payment-acceptance/integration-scenarios/widget/quick-start), [уведомлений](https://yookassa.ru/developers/using-api/webhooks).

Известные ограничения: тестовые реквизиты ЮKassa не входят в репозиторий, реальный платёж не выполнялся; нет реального эквайринга, доставки, автоматического возврата денег и юридических документов; бот и телефонный сценарий требуют ваших учётных данных и HTTPS URL; демоснимки синтетические и могут повторяться у разных товаров; `localStorage` не синхронизирует корзину между устройствами. Инфраструктура публичного сервера подготовлена отдельно, но реальный запуск и внешние интеграции без сервера и домена не проверены.

## Кабинет и карточка товара

Текущие заказы, завершённые покупки, заявки «Хочу заказать» и избранное открываются на отдельных страницах кабинета. На главной странице кабинета есть горизонтальная лента «Вы смотрели». В Mini App данные связаны с Telegram ID из проверенного `initData`, а в Chrome — с тем же ID после входа по коду или через Telegram Login. Сохранённая ссылка на гостевой заказ по-прежнему открывает конкретный заказ.

В карточке показываются примерные сроки доставки по городу (от/до дней задаются для товара в админке), аксессуары, отзывы с оценками, вопросы и ответы. Отзыв может написать один раз только вошедший через Telegram покупатель после оплаты и выдачи товара. Он появляется после публикации сотрудником в админке; старые анонимные отзывы скрываются миграцией. Вопрос тоже отправляется из Telegram-аккаунта, поэтому повторно вводить имя не нужно; вопрос ждёт публикации сотрудником. Подборки редактируются в админке. «С этим товаром покупают» настраивается связями товара с аксессуарами; блок похожих внизу берёт другие видимые товары из той же категории. В браузере кнопка «Поделиться» копирует публичную ссылку, а в Mini App открывает выбор чата Telegram и подставляет ссылку Mini App при настроенном username и short name бота.

По выданному заказу покупатель может отправить заявку на возврат отдельной позиции. Магазин меняет статус заявки в админке и связывается с покупателем; денежный возврат этот шаг не выполняет.
