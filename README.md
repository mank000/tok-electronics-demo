# ток. — учебный магазин электроники

Одна адаптивная Django-страница работает в обычном браузере и как Telegram Mini App. В проекте есть PostgreSQL, Django Admin, каталог из 24 демотоваров, корзина, заказ, демооплата, бот и очередь уведомлений. Продаж и списания денег нет: платежи учебные, юридические страницы — заглушки.

## Запуск с нуля

Нужны Docker и Docker Compose. Команды выполняются в каталоге проекта:

```bash
cp .env.example .env
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Вставьте случайное значение в `DJANGO_SECRET_KEY`, создайте **другие** случайные значения для `POSTGRES_PASSWORD` и `PAYMENT_WEBHOOK_SECRET`. `BOT_TOKEN` можно оставить пустым для проверки браузерного режима. Затем:

```bash
docker compose up -d --build web
docker compose exec web python manage.py seed_catalog
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py test store
```

Откройте <http://localhost:8008/> и админку <http://localhost:8008/admin/>. Миграции применяются при старте `web`. Команда `seed_catalog` идемпотентна: повторный запуск не создаёт дубликаты и сохраняет уже отредактированные товары. Остановить: `docker compose down` (данные останутся в volumes). `docker compose down -v` удалит БД и изображения.

## Переменные окружения

Пример без секретов — [`.env.example`](.env.example). `.env` игнорируется Git.

| Переменная | Назначение |
| --- | --- |
| `DJANGO_SECRET_KEY` | Секрет Django, длинное случайное значение |
| `DJANGO_DEBUG` | `1` для локальной демонстрации; демооплата требует `1` |
| `DJANGO_ALLOWED_HOSTS` | Хосты без схемы, через запятую |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Полные origin с `https://` для туннеля |
| `POSTGRES_*` | База, пользователь, пароль PostgreSQL |
| `BOT_TOKEN` | Токен BotFather; для браузерного пути не нужен |
| `BOT_USERNAME` | Username бота без `@` |
| `BOT_APP_SHORT_NAME` | Short name Mini App, созданного в BotFather |
| `PUBLIC_BASE_URL` | Публичный HTTPS URL туннеля для запасной кнопки бота |
| `SHOP_CHAT_ID` | ID отдельного чата магазина |
| `PAYMENT_WEBHOOK_SECRET` | Отдельный секрет HMAC платежных событий |
| `DEMO_PAYMENTS` | `1` включает учебную оплату только при `DJANGO_DEBUG=1` |

Секреты, БД, пользовательские фотографии и `.env` не входят в Git. В текущем Compose медиа отдаётся Django только при `DEBUG=1`: это конфигурация для демонстрации, не для боевого размещения.

## Каталог и покупка в браузере

1. Найдите товар поиском или разделом, отсортируйте по цене. Скрытые товары не показываются.
2. На карточке товара со статусом «Под заказ» оставьте заявку «Хочу такой». Остальные товары добавьте в корзину.
3. Измените количество в корзине. Она сохраняется в `localStorage` этого браузера.
4. Оформите заказ: имя, телефон, получение, адрес для доставки, оплата, согласие. Для отправки в регионы оплата при получении запрещена. Сервер заново читает текущие цены и сохраняет их в позициях заказа.
5. Сохраните непредсказуемую ссылку на страницу заказа. Для онлайн-оплаты откройте демостраницу, нажмите «Отказ», вернитесь к заказу и повторите с «Оплата прошла».

Страницы обработки данных и оферты явно помечены как заглушки. Перед настоящими продажами их нужно заменить. Оплата при получении не вызывает демооплату.

## Telegram Mini App и бот

1. В `@BotFather` создайте бота (`/newbot`) и Mini App для этого бота (`/newapp`). Получите токен, username и короткое имя приложения. Настройте HTTPS URL приложения после запуска туннеля.
2. Создайте отдельную группу/чат магазина, добавьте бота, отправьте `/chatid`. Бот ответит ID чата; запишите его в `SHOP_CHAT_ID`. Для сообщений покупателю он должен сначала открыть личный чат с ботом и нажать `/start`. При отсутствии разрешённого чата уведомление остаётся в админке со статусом ошибки.
3. Запишите `BOT_TOKEN`, `BOT_USERNAME`, `BOT_APP_SHORT_NAME`, `SHOP_CHAT_ID` в `.env` и запустите `docker compose up -d --build web`; затем `docker compose --profile bot up -d bot`. Если бот уже получает обновления через webhook, отключите его перед long polling.
4. Для локальной проверки HTTPS установите `cloudflared` и запустите `cloudflared tunnel --url http://localhost:8008`. Если QUIC не соединяется с edge, используйте `cloudflared tunnel --url http://localhost:8008 --protocol http2`. Скопируйте выданный `https://...trycloudflare.com` URL. В `.env` задайте `DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,<имя-хоста-туннеля>`, `DJANGO_CSRF_TRUSTED_ORIGINS=http://localhost:8008,https://<имя-хоста-туннеля>` и `PUBLIC_BASE_URL=https://<имя-хоста-туннеля>`. Примените: `docker compose up -d --force-recreate web` и `docker compose --profile bot up -d --force-recreate bot`. В BotFather установите этот HTTPS URL для Mini App.
5. Откройте `https://t.me/<bot_username>/<app_short_name>?startapp=product_phones-1`: должна открыться карточка товара. Из чата бота нажмите кнопку каталога и пройдите оформление. Проверьте заказ, оплату, уведомления в личном чате и чате магазина.

`Telegram.WebApp.initData` передаётся серверу без доверия к `initDataUnsafe`; сервер проверяет HMAC, `auth_date` и ID пользователя. Запрос контакта — отдельное разрешение. После согласия номер приходит боту как сообщение и подставляется в форму, если успел прийти; ручной ввод доступен всегда. Callback сам номер не содержит.

Демооплата открывается через `Telegram.WebApp.openLink` во внешнем браузере. **Mini App остаётся открытым**. После оплаты вернитесь в него и обновите страницу заказа; внешний браузер также показывает возврат к заказу. Ссылка на заказ является ключом гостевого доступа, не передавайте её посторонним.

Для короткой записи экрана на телефоне: начните с `/start` и кнопки каталога → откройте товар по прямой ссылке → добавьте другой товар в корзину → оформите заказ → во внешнем браузере нажмите «Отказ» → повторите и нажмите «Оплата прошла» → вернитесь к заказу → покажите два чата с уведомлениями и в админке смените статус/укажите трек-номер → покажите уведомление покупателю. Уберите из записи реальные телефоны, токены и приватную ссылку заказа.

## Админка и уведомления

В админке доступны разделы, товары с несколькими изображениями, цены, наличие и скрытие, заказы, заявки, платежные события и очередь уведомлений. На странице товара видно количество заявок «Хочу такой». У заказа можно менять статус и трек-номер; они ставят сообщения в очередь. Бот отправляет очередь независимо от транзакции заказа. Ошибки видны в «Уведомлениях»; выделите неотправленные и выберите действие «Повторить отправку выбранных уведомлений».

Загружаемые изображения приводятся к WebP (основное изображение до 1200×1200, превью до 480×480). Источник демоизображений — **семь оригинальных синтетических фотоснимков, созданных OpenAI imagegen для этого проекта**; сжатые исходники лежат в `store/seed_photos/`. Пять снимков повторно используются в соответствующих разделах, а у первых смартфона и ноутбука есть второй ракурс. Каждый товар получает локальный снимок; сторонних hotlink URL и лицензий на чужие фото нет. Это обобщённые изображения, не фотографии конкретных вымышленных моделей. Для настоящего магазина замените их собственными снимками.

## Проверки и платежный обработчик

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py test store -v 2
docker compose exec web python manage.py seed_catalog
docker compose exec web python manage.py seed_catalog
```

Последние две команды должны сохранить число товаров 24. Платежный endpoint `/api/payment/webhook/` принимает JSON `{"event_id":"...","attempt":"UUID","status":"paid|declined"}` и заголовок `X-Payment-Signature` = HMAC-SHA-256 от **сырых байтов** тела с `PAYMENT_WEBHOOK_SECRET`. События повторно не применяются. Браузер не вызывает этот endpoint: кнопки демооплаты вызывают серверный сценарий, который использует ту же функцию обработки событий. Для подключения реального провайдера нужен отдельный адаптер его формата, подтверждение суммы/валюты и его способ подписи; текущая схема предназначена для учебной имитации.

Известные ограничения: нет реального эквайринга, доставки и юридических документов; бот и телефонный сценарий требуют ваших учётных данных и HTTPS URL; демоснимки синтетические и могут повторяться у разных товаров; `localStorage` не синхронизирует корзину между устройствами. Для боевого запуска нужны отдельная настройка статических/медиа файлов, HTTPS reverse proxy, HTTPS-only cookies, мониторинг и замена `DEBUG=1`.
